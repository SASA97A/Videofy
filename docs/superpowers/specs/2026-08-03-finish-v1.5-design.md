# Finish v1.5 Properly — Design Spec

**Date:** August 3, 2026
**Branch:** `version/1.5`
**Status:** Approved

## Problem

The original `PLANNING.md` for v1.5 was written after implementation (committed
34 minutes after the "FINAL: v1.5 Complete" commit). It never existed as a
pre-implementation artifact. Consequently, v1.5 shipped with:

1. **Dead services** — `CodecService` and `EncodingProfileService` are never
   referenced outside their own files. The encoder/audio/profile dropdowns bind
   to hardcoded string lists (`MainWindowViewModel.cs:44-45`), not the services.
2. **Cosmetic UI** — `SelectedProfile` and `SelectedAudioCodec` are never read
   by the encoding pipeline. Selecting "NVIDIA Fast" or "Opus" does nothing.
3. **Stub shortcut** — Ctrl+P only writes a log line; it never calls
   `TogglePause()`.
4. **Theme never applies on selection** — `SettingsWindow` saves the theme name
   to disk, but the theme is only applied at startup in
   `MainWindow.OnOpened()`. Changing the theme requires a restart.
5. **Zero automated tests** — the plan promised unit/integration/E2E testing;
   no test project exists.
6. **Obsolete API warnings** — the build emits 2 CS0618 warnings for
   `DragEventArgs.Data` and `GetFileNames()`.

## Goal

Make every v1.5 feature genuinely work — no dead code, no cosmetic UI, no stubs
— verified by real automated tests and build gates.

## Architecture

- **Vertical slices**, one per feature. Each task = write failing xUnit test →
  implement/wire → build + test gate → commit.
- New **`Videofy.Tests`** xUnit project (net8.0) references the main project.
- All logic lives in testable services / ViewModels. UI stays thin.
- Hardcoded lists get replaced by the services that were built but never wired,
  with graceful fallback when FFmpeg is missing.

## Scope (tasks)

1. **Test infrastructure** — new xUnit project, one wiring-sanity test, green.
2. **CodecService wired** — `AvailableEncoders` + `AvailableAudioCodecs` come
   from `CodecService` (fallback to current hardcoded lists if FFmpeg missing).
3. **EncodingProfileService wired + auto-fill** — selecting a profile populates
   CRF / resolution / fps / audio / encoder in the UI; the pipeline uses them.
4. **Audio codec actually used** — `SelectedAudioCodec` flows into FFmpeg args
   via a new `CompressAsync` parameter (`-c:a`, `-b:a`).
5. **Ctrl+P really pauses** — keyboard shortcut calls `TogglePauseCommand`.
6. **Theme applies immediately** — saving Settings re-applies the theme without
   restart.
7. **Obsolete APIs removed** — drag & drop migrated to Avalonia 11's
   `DataTransfer`/`GetFiles`, clearing the 2 build warnings.
8. **Verification gate + honest docs** — full build/test run, launch smoke
   check, then rewrite v1.5 docs to match reality.

## Out of scope

- Custom profile/codec/theme editors (v1.6+).
- FFmpeg arg builder rework beyond the audio-codec parameter.
- Upgrading Avalonia or restructuring existing views.

## Success criteria

- `dotnet build` → 0 errors, 0 warnings.
- `dotnet test` → all tests green.
- Every dropdown is powered by a service (or a documented fallback).
- Selecting a profile changes the encode settings and the output respects them.
- Ctrl+P pauses/resumes an active encode.
- Theme change applies immediately and persists.
- Docs state only what is true.
